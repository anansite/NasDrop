# 上传状态与自动刷新实施记录

**Goal:** 上传开始立即看到进度，文件发送后立即可见，服务端确认后自动校正目标目录。

**Architecture:** 沿用前台上传服务和传输中心。StateFlow 保存带稳定 ID、批次与目标目录的上传快照；列表临时合并尚未被远端列出的上传项，目录刷新去重合并并在后台执行。

**Tech Stack:** Kotlin、Compose、coroutines、OkHttp；JUnit 验证上传状态与目录合并行为。

**Spec:** 用户本轮请求；交接文档 `C:/Users/admin/WorkBuddy/NasDrop-交接文档.md`（含凭据，不复制、不提交）。

## 约束与交互

- App 内三个上传入口均自动打开传输中心；外部分享显示对应批次进度。
- 区分排队、发送、等待服务端确认、完成与失败；只有 PUT 成功才报完成。
- 成功或失败记录保留至用户清除；运行中任务不提供无效的清除/暂停按钮。
- 不改网络路由、证书设置、服务端配置；不推送或发布。
- 已获修复及体验优化授权，沿用当前技术栈，自行完成实现与验证。

## Review Focus

- 连续多次上传、同一 URI 重复提交：稳定 ID，不覆盖别的批次。
- PUT 响应慢或失败：已发送与完成分开；不假报成功，不丢原有覆盖目标。
- 冷启动或重建页面：从状态快照恢复可见文件，不依赖一次性事件。
- 目录响应晚到、导航切换：保留待确认条目，不串目录。
- 缩略图慢或失败：不阻塞任务完成和批次通知。

## 实现及验证结果

- 事件接收不再同步等待 PROPFIND；待同步项与服务器原始目录分开保存，旧目录响应不会吞掉刚上传的文件。
- 目录请求按版本应用；确认后的刷新按目标目录合并。远端目录尚未包含文件时，后台最多补查三次，间隔 1/2/4 秒；不延迟任务完成。
- 已发送与 PUT 成功独立展示。未知大小文件也报告最终进度；大文件响应丢失不允许 OkHttp 隐式重传，异常保留原始原因。

- 分享启动到任务发布之间禁止提前返回释放 URI 授权；进程重建导致队列丢失时显示中断，避免无限等待。
